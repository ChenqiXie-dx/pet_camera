# 心系宠物 - 需求文档

## 1. 项目概述

### 1.1 项目名称
心系宠物 (PetCam)

### 1.2 项目目标
利用旧安卓手机作为视频采集终端，搭建一个基于 WebRTC 的实时视频监控网站，让用户随时通过网页查看宠物动态，支持双向语音对讲、云端录像回放和动作检测通知。

### 1.3 系统范围

| 组成部分 | 说明 |
|---------|------|
| 安卓采集端 | 旧安卓手机 APP，负责视频采集、推流、录音、动作检测 |
| 云服务端 | 部署在阿里云，负责 WebRTC 信令、视频存储、设备管理 |
| Web 客户端 | Vue.js 单页应用，用户通过浏览器访问（单用户，无需登录） |

### 1.4 设计说明

**单用户简化设计**：本系统设计为单用户使用场景，网页端无需登录即可访问。设备通过 App 配对后自动与系统绑定。

## 2. 系统架构

### 2.1 整体架构

```
┌─────────────┐     WebRTC      ┌─────────────┐     WebRTC      ┌─────────────┐
│  安卓手机    │ ◄────────────► │   云服务     │ ◄────────────► │   浏览器     │
│  (采集端)    │    信令通道      │  (信令+存储)  │                │  (Web端)    │
└─────────────┘                 └─────────────┘                └─────────────┘
       │                              │
       │     ┌─────────────────┐      │
       └────►│   阿里云服务器    │◄─────┘
             │  - MariaDB       │
             │  - WebRTC 信令    │
             │  - 录像存储       │
             └─────────────────┘
```

### 2.2 技术选型

| 层级 | 技术方案 | 说明 |
|------|---------|------|
| 安卓端 | 原生 Android (Kotlin) | 相机 Capture, WebRTC Mobile SDK |
| 前端 | Vue.js 3 + Vite | SPA 应用，用户界面 |
| 后端 | Node.js + Express | WebRTC 信令服务，API 服务 |
| 数据库 | MariaDB | 用户数据、设备数据、录像元数据 |
| 实时通信 | WebRTC | 点对点视频/音频传输 |
| 录像存储 | 文件系统 + MariaDB 索引 | 50GB 存储空间 |
| 动作检测 | TensorFlow Lite (移动端) | 本地实时检测 |

### 2.3 网络拓扑

- 安卓采集端通过 NAT/Firewall 连接阿里云服务器
- Web 端用户通过浏览器 HTTPS 访问阿里云
- WebRTC 直连失败时通过 TURN 中继

## 3. 功能需求

### 3.1 安卓采集端 APP 功能

#### 3.1.1 实时视频推流
- 采集前置/后置摄像头视频
- 通过 WebRTC 推送到云端服务器
- 支持分辨率选择：480p / 720p / 1080p
- 自适应码率调整（网络波动时自动降码率）

#### 3.1.2 本地录制 + 云端存储
- APP 端本地录制视频文件（MP4 格式）
- 录制完成后自动上传到云端存储
- 云端存储保留 3 天后自动删除（循环覆盖）
- 支持断点续传，网络恢复后继续上传

#### 3.1.3 动作检测与通知
- 使用 TensorFlow Lite 本地运行动作检测模型
- 检测到宠物动作时：
  - 在 APP 内显示通知
  - 推送消息到云端
  - 触发短视频录制（动作发生前后各 5 秒）
- 动作事件列表可查看

#### 3.1.4 双向语音对讲
- APP 持续采集音频
- 支持接收来自 Web 端的音频并播放
- Web 端可随时发起对讲

#### 3.1.5 设备绑定与配置
- 首次启动自动生成设备唯一 ID（UUID）
- 设备自动绑定到系统（默认用户 ID = 1）
- 返回设备 Token 用于后续 Socket.IO 认证
- 可配置项：分辨率、码率、录制时长、动作检测灵敏度

### 3.2 Web 端功能

#### 3.2.1 设备列表
- 首页展示已绑定设备列表
- 显示设备在线/离线状态
- 无需登录即可访问

#### 3.2.2 实时视频查看
- 首页展示已绑定设备列表
- 点击设备进入实时监控
- 支持全屏播放
- 显示设备在线状态

#### 3.2.3 双向语音对讲
- 监控页面提供对讲按钮
- 按住说话，松开结束
- 设备端实时接收并播放

#### 3.2.4 录像回放
- 按日期选择录像文件
- 时间轴拖动播放
- 支持倍速播放（0.5x / 1x / 2x）
- 录像文件下载到本地

#### 3.2.5 动作事件通知
- 动作事件列表页面
- 显示动作发生时间、缩略图
- 点击查看动作发生时的短视频

### 3.3 后端服务功能

#### 3.3.1 设备管理 API
| 接口 | 方法 | 说明 |
|------|------|------|
| /api/devices | GET | 获取设备列表 |
| /api/devices | POST | 创建设备/设备配对 |
| /api/devices/:id | GET/DELETE | 设备详情/解绑 |
| /api/devices/:id/status | POST | 更新设备状态（设备端调用） |

#### 3.3.3 WebRTC 信令服务
- Socket.IO 实现信令通道
- 支持房间管理（设备-Web端配对）
- ICE Candidate 交换
- SDP Offer/Answer 交换

#### 3.3.4 录像存储管理
| 接口 | 方法 | 说明 |
|------|------|------|
| /api/recordings | GET | 获取录像列表 |
| /api/recordings/:id | GET | 播放/下载录像 |
| 自动清理 | - | 3 天前录像自动删除 |

#### 3.3.5 动作事件 API
| 接口 | 方法 | 说明 |
|------|------|------|
| /api/events | GET | 获取动作事件列表 |
| /api/events/:id/video | GET | 获取事件关联视频 |

## 4. 非功能需求

### 4.1 性能要求

| 指标 | 要求 |
|------|------|
| 视频延迟 | WebRTC 端到端延迟 < 500ms |
| 视频帧率 | 25-30 fps |
| 支持并发 | 单台服务器支持 10 路同时观看 |
| 信令响应 | API 响应时间 < 200ms |

### 4.2 存储需求

| 类型 | 容量 | 说明 |
|------|------|------|
| 录像存储 | 50 GB | 3 天循环存储 |
| 单个录像 | 最大 100 MB | 自动分段 |
| 事件短视频 | 10 秒/个 | 动作触发录制 |

### 4.3 安全要求

- 所有 API 必须通过 HTTPS 访问
- WebRTC 流量加密（DTLS）
- 设备认证使用 JWT Token（设备端）
- JWT Token 有效期 24 小时
- 设备 Token 用于 Socket.IO 连接认证

### 4.4 可用性要求

- 设备端断线自动重连
- 服务器端异常自动告警
- 录像上传失败自动重试（最多 3 次）

## 5. 技术指标

### 5.1 视频参数建议

| 分辨率 | 码率 | 帧率 | 适用场景 |
|--------|------|------|---------|
| 480p | 1000 kbps | 25fps | 低带宽 |
| 720p | 2000 kbps | 25fps | 推荐 |
| 1080p | 4000 kbps | 25fps | 高带宽 |

### 5.2 WebRTC 配置

```
{
  "iceServers": [
    { "urls": "stun:stun.l.google.com:19302" },
    { "urls": "turn:your-turn-server.com", "username": "...", "credential": "..." }
  ],
  "video": { "width": 1280, "height": 720, "frameRate": 25 },
  "audio": { "echoCancellation": true, "noiseSuppression": true }
}
```

### 5.3 服务器资源需求

| 资源 | 最低配置 | 推荐配置 |
|------|---------|---------|
| CPU | 2 核 | 2 核 |
| 内存 | 2 GB | 4 GB |
| 带宽 | 5 Mbps | 10 Mbps |
| 磁盘 | 50 GB | 100 GB |

### 5.4 数据库表结构（概要）

```
devices
├── id (INT, PK)
├── device_id (VARCHAR, UNIQUE)      -- 设备生成的唯一ID
├── user_id (INT)                    -- 默认用户ID=1（单用户设计）
├── name (VARCHAR)
├── status (ENUM: online/offline/busy)
├── resolution (ENUM)
├── bitrate (INT)
├── motion_sensitivity (FLOAT)
├── last_seen (DATETIME)
├── created_at (DATETIME)

recordings
├── id (INT, PK)
├── device_id (INT, FK)
├── filename (VARCHAR)
├── filepath (VARCHAR)
├── duration (INT)
├── size (INT)
├── created_at (DATETIME)

events
├── id (INT, PK)
├── device_id (INT, FK)
├── type (VARCHAR)
├── video_id (INT, FK, nullable)
├── thumbnail (VARCHAR)
├── created_at (DATETIME)
```

## 8. 产品优化建议（按优先级排序）

### 优先级说明

| 优先级 | 定义 | 依据 |
|--------|------|------|
| P0 | 核心功能，缺失产品不可用 | 竞品标配，用户预期 |
| P1 | 重要功能，影响用户体验 | 用户留存关键 |
| P2 | 优化功能，提升体验 | 差异化竞争力 |
| P3 | 锦上添花，有则更好 | 可后续迭代 |

---

### P0 - 核心功能（必须实现）

#### 1. 双向语音对讲

**用户场景**：主人上班时想念宠物，可以喊它名字让它回头看镜头。

**实现说明**：
- Android 端：采集音频 + 接收 Web 端音频并通过扬声器播放
- Web 端：采集音频（按住说话按钮） + 接收 Android 音频并播放
- WebRTC 需要交换音频轨道（目前只交换视频轨道）

**技术方案**：WebRTC AudioTrack 交换，与视频类似

**状态**：需求文档已定义，待开发

---

#### 2. 竖屏视频满屏显示

**用户场景**：用旧手机做摄像头通常是竖屏放置，横屏画面有大量黑边，体验差。

**实现说明**：
- Web 端 Monitor.vue 视频容器不再固定 16:9 比例
- 改为宽度 100%，高度自适应
- 视频使用 `object-fit: cover` 填满容器

**状态**：需求已列入开发计划，待开发

---

### P1 - 重要功能（影响留存）

#### 3. 一键截图/录屏分享

**用户场景**：看到宠物可爱瞬间，一键生成短视频或图片分享到微信朋友圈。

**实现说明**：
- Web 端添加截图按钮（canvas 截取当前帧）
- 添加录屏按钮（录制最近 N 秒的视频流）
- 生成可分享的链接或直接下载

**产品价值**：社交传播，带来新用户

---

#### 4. 异常状态告警

**用户场景**：
- 宠物长时间不动（可能生病或出事）
- 突然有大声音/陌生人
- 设备断网

**实现说明**：
- Android 端检测画面变化率
- 检测音频异常（突然的大声音）
- 断网时发送推送通知
- Web 端仪表盘显示异常状态

**产品价值**：解决用户"宠物独自在家不放心"的核心理念

---

#### 5. 画质自适应

**用户场景**：不同网络环境下都能流畅观看。

**实现说明**：
- 检测网络质量（丢包率、延迟）
- 自动切换分辨率/码率
- Web 端显示当前画质

**产品价值**：恶劣网络环境也能保持连接

---

### P2 - 优化功能（差异化竞争力）

#### 6. 云端录像存储

**用户场景**：换手机后历史录像还在，不依赖本地存储。

**实现说明**：
- 阿里云 OSS 存储录像文件
- 数据库存储元数据
- 提供录像列表和回放功能

**产品价值**：数据更安全，付费转化点

---

#### 7. 多设备管理

**用户场景**：家里多台手机做摄像头，一个账号管理。

**实现说明**：
- 一个账号绑定多个设备
- 同时查看多个摄像头画面（画中画或分屏）

**产品价值**：满足多房间监控需求

---

#### 8. 逗宠功能

**用户场景**：远程逗宠物玩，增加互动。

**实现说明**：
- 播放声音吸引宠物注意
- 投喂零食（需要硬件支持）

**产品价值**：差异化功能，增加用户粘性

---

### P3 - 锦上添花（后续迭代）

#### 9. 宠物 AI 相册

**用户场景**：自动识别宠物脸，生成可爱瞬间合集。

**实现说明**：
- TensorFlow Lite 宠物识别
- 自动打标签、生成相册

---

#### 10. 智能精彩时刻

**用户场景**：每天自动生成宠物视频集锦。

**实现说明**：
- AI 分析录像，提取精彩片段
- 自动拼接成短视频
